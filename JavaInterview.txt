Q1.   What is Java?
Ans. Java is a high-level, object-oriented, platform-independent programming language used to develop different types of applications such as web, desktop, and enterprise applications.



Q2.   Why is Java platform-independent?
Ans. Java is platform-independent because the Java compiler converts source code into bytecode, and the same bytecode can run on any operating system that has a compatible JVM.



Q3. What is JVM?
Ans. JVM (Java Virtual Machine) is a runtime environment that executes Java bytecode. It allows the same Java bytecode to run on different operating systems.



Q4. What is JDK?
Ans. JDK (Java Development Kit) is a software development kit used to develop Java applications. It contains tools like the Java compiler (javac), JVM, and other development tools.



Q5. What is JRE?
Ans. JRE (Java Runtime Environment) provides the environment required to run Java applications. It contains the JVM and Java libraries needed for execution.



Q6. What is the difference between JDK, JRE, and JVM?

Q7. Is Java 100% object-oriented? Why or why not?
Ans. Java is not a pure object-oriented language because it supports primitive data types like int, char, and boolean, which are not objects. It also supports static members that can be accessed without creating an object.

Q10. What is the difference between method overloading and method overriding?
Ans. Method Overloading:  Same method name with different parameters in the same class. It is compile-time polymorphism.

Method Overriding:   A child class provides its own implementation of a method inherited from the parent class. It is runtime polymorphism.

            class Calculator {
            
                // Overloading
                int add(int a, int b) {
                    return a + b;
                }

                int add(int a, int b, int c) {
                    return a + b + c;
                }
            }

            class Animal {
                void sound() {
                    System.out.println("Animal sound");
                }
            }

            class Dog extends Animal {
            
                // Overriding
                @Override
                void sound() {
                    System.out.println("Dog barks");
                }
            }

Q20. What is the difference between String, StringBuilder, and StringBuffer?
Ans. String is an immutable class in Java used to represent a sequence of characters.

    //String name = "Java";

StringBuilder is a mutable class used to create and modify a sequence of characters. It is generally faster than StringBuffer but is not thread-safe.

    //StringBuilder sb = new StringBuilder("Java");
    //sb.append(" Programming");
    //System.out.println(sb); // Java Programming

StringBuffer is a mutable and thread-safe class used to modify a sequence of characters. It is generally slower than StringBuilder because its methods are synchronized.

    //StringBuffer sb = new StringBuffer("Java");
    //sb.append(" Programming");
    //System.out.println(sb); // Java Programming
    
String        → Immutable
StringBuilder → Mutable + Not Thread-safe + Faster
StringBuffer  → Mutable + Thread-safe + Synchronized



Q21. Why is String immutable in Java?
Ans. String is immutable because once a String object is created, its value cannot be changed. Any modification creates a new String object. This provides security, thread safety, and allows efficient use of the String Pool.

Q25. What is the difference between Stack memory and Heap memory in Java?

Q29. What is the difference between final, finally, and finalize()?
Ans. final is a keyword used to prevent changes.
        final int x = 10;

        final variable → value cannot be changed
        final method → cannot be overridden
        final class → cannot be inherite

    finally is a block that normally executes after try/catch, whether an exception occurs or not.
        try {
            int x = 10 / 0;
        } catch (Exception e) {
            System.out.println("Error");
        } finally {
            System.out.println("Always executes");
        }

    finalize() was a method that could be called by the garbage collector before an object was reclaimed, but it is deprecated and should not be used in modern Java.

        final     → keyword → prevent change
        finally   → block   → cleanup code
        finalize  → method  → deprecated
